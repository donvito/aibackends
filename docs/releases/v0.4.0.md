# aibackends v0.4.0 — Liquid AI Models, Device Controls, and Tool Calling

This release adds first-class Liquid AI LFM2.5 model profiles, makes local
runtime hardware and quantization choices configurable, and adds utilities for
working with native Pythonic tool calls.

## Highlights

### Liquid AI LFM2.5 support

- `LFM25_2_6B` is available on both `transformers` and `llamacpp`, with
  Liquid AI's recommended generation defaults.
- `LFM25_VL_3B` adds vision support on `llamacpp`, including ChatML multimodal
  handling and automatic `mmproj` projector downloads.
- New examples cover native tool calling and receipt extraction from images.

### Hardware and generation controls

- Use `device="cpu"` or `device="gpu"` with either local runtime.
- Configure GGUF `quantization` per call or in a model profile; LFM2.5
  defaults to `Q4_K_M`.
- Generation options including `top_k`, `top_p`, and
  `repetition_penalty` now flow through runtime calls and model profiles.
- `transformers` supports `dtype` load options and
  `skip_special_tokens` decoding.

### Tool-call parsing

The new `aibackends.core.tool_calls` module parses native Pythonic tool-call
responses, including responses with or without tool-call markers. It exposes
`ToolCall`, `extract_tool_calls`, `strip_reasoning`, and `clean_answer`.

## Other changes

- Added CPU benchmark reports for LFM2.5-2.6B and LFM2.5-VL-3B.
- Added a tool-call accuracy evaluation suite and dated reports.
- Added a CUDA Docker image configuration for GPU clouds including RunPod and
  Modal.
- `parse_json_content` now ignores JSON drafted inside reasoning blocks.
