# aibackends v0.6.0 — GLiNER2.5 Span-Free Information Extraction

This release adds a dedicated extraction capability to aibackends. GLiNER2.5
runs locally as its own backend — it does not go through the configured
generative runtime — so entity extraction, classification, and knowledge-graph
building stay fast, offline, prompt-free, and independent of whichever LLM you
are serving.

## Highlights

### GLiNER2.5 extraction backend

`fastino/gliner2.5-*-v1` is now a first-class backend with three variants
selectable by name, or any Hugging Face repo id:

| Variant | Model | Params | Notes |
|---|---|---|---|
| `small` | `fastino/gliner2.5-small-v1` | 74M | Fastest on CPU |
| `base` | `fastino/gliner2.5-base-v1` | 194M | Default, English |
| `multi` | `fastino/gliner2.5-multi-v1` | 287M | Multilingual |

Everything is zero-shot: the labels are supplied per call, there is no
fine-tuning, no prompt, and no in-context examples.

### Typed extraction tasks

```python
from aibackends import classify_text, extract_entities, extract_graph

text = "Alice Reyes emailed alice@example.com from Acme's Paris office."

entities = extract_entities(
    text,
    labels=["person", "email", "organization", "location"],
    model="small",
    device="cpu",
)
for entity in entities.entities:
    print(entity.label, entity.text, entity.start, entity.end, entity.confidence)

routing = classify_text(
    "My card was charged twice for the same order.",
    labels=["billing", "bug_report", "feature_request"],
)
print(routing.value("label"))

graph = extract_graph(
    text,
    entities=["person", "organization", "location"],
    relations=[
        {"name": "works_for", "head": "person", "tail": "organization"},
        {"name": "located_in", "head": "organization", "tail": "location"},
    ],
)
print(graph.triples())
```

Results are the `EntityExtraction`, `TextClassification`, and `KnowledgeGraph`
models from `aibackends.schemas.extraction`. Every task has an `_async`
variant, and all of them are exported from the top-level `aibackends` package
as well as `aibackends.tasks`.

### What the backend covers

- **Entities** — zero-shot labels with character offsets and confidences,
  span attributes for qualified spans, unlimited span lengths (clause-level
  entities, not just short noun phrases), and `long_document=True` chunking
  with configurable `chunk_size` / `chunk_overlap`.
- **Classification** — multiple tasks in one pass, multi-label mode, per-label
  probabilities, `min_labels` / `max_labels` / `threshold` / `default` /
  `instruction` per task, and `implies` / `excludes` / `iff` constraints with
  a `feasible` flag when a constraint set cannot be satisfied.
- **Graphs** — joint entity-relation decoding, so every relation endpoint
  exists in the result and endpoint types are enforced, with `unique_head` and
  `no_self_loops` schema options.

### Device and batch controls

- Run on `cpu`, `gpu`, `cuda`, `cuda:<index>`, or `mps`.
- The model is loaded once per process and device and reused across calls.
- `extract_entities_batch(...)` and `classify_texts(...)` use the model's
  native batch API (default `batch_size=8`).

### Install

```bash
pip install aibackends[extraction]
```

The new `extraction` extra pulls in `gliner2[local]` and `protobuf`; both are
also included in the `all` extra.

### CLI

```bash
aibackends task extract-entities --input contract.txt --labels party,monetary_amount --model small
aibackends task classify-text --input "Refund my card" --labels billing,bug,feature
aibackends task extract-graph --input "Alice works for Acme in Paris." \
    --entities person,organization,location \
    --relation works_for:person:organization --relation located_in:organization:location
```

`--entities` takes a comma-separated list and `--relation` is repeatable,
formatted `name:head:tail`.

## Performance

Measured on a 4-core x86_64 CPU with no GPU (full report in
`benchmarks/reports/2026-08-25_gliner25-cpu.md`):

| Model | Params | Load (s) | Entities (ms) | Classify (ms) | Graph (ms) | Batch/item (ms) |
|---|---|---|---|---|---|---|
| small | 74M | 4.4 | 21 | 20 | 31 | 7 |
| base | 194M | 2.9 | 50 | 51 | 61 | 18 |
| multi | 287M | 4.1 | 54 | 54 | 68 | 20 |

Native batching is roughly 3x cheaper per item than single calls (147 items/s
on `small`, 55 on `base`). Long-document mode scales close to linearly with
input length: `small` runs a 2,000-word document in ~1.05 s.

## Accuracy

Zero-shot, no fine-tuning and no in-context examples, 150 samples per dataset
(full report in `evals/reports/2026-08-25_gliner25-zero-shot.md`):

| Model | ag_news acc | rotten_tomatoes acc | CrossNER politics micro-F1 |
|---|---|---|---|
| small | 70.0% | 75.3% | 0.503 |
| base | 71.3% | 79.3% | 0.605 |
| multi | 73.3% | 69.3% | 0.587 |

NER uses exact character-offset matching, which is stricter than token-level
or partial-overlap scoring.

## Examples and notebook

Seven runnable demos under `examples/gliner25/` cover PII detection with
offset redaction, clause-length spans, knowledge graphs, constrained agent
routing, clinical span attributes, full-contract chunked extraction, and
zero-shot multilingual NER. An executed Colab notebook lives at
`examples/notebooks/gliner25_extraction_colab.ipynb`.

## Other changes

- Added a pluggable extraction backend registry
  (`register_extraction_backend`, `get_extraction_backend`,
  `list_extraction_backends`) under `aibackends.backends.extraction`.
- Documented the capability backend architecture across the PII, moderation,
  and extraction backends in `docs/architecture.md`, `docs/concepts.md`, and
  `docs/extending.md`.
- Extraction tasks are now exported from the top-level `aibackends` package,
  matching the moderation tasks added in v0.5.0.
