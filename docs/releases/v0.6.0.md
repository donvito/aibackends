# aibackends v0.6.0 — GLiNER 2.5 Span-Free Extraction

This release adds GLiNER 2.5 as a first-class extraction backend. The model
scores entity start and end boundaries instead of enumerating spans, which is
what makes long-document extraction, unlimited span length, joint graphs,
constrained classification, and span attributes possible on a small local
encoder.

It does not go through the configured generative runtime.

## Highlights

### GLiNER 2.5 extraction backend

Three Apache-2.0 checkpoints, selected with `model=`:

- `gliner25-small` → `fastino/gliner2.5-small-v1` (74M, default, CPU-friendly)
- `gliner25-base` → `fastino/gliner2.5-base-v1` (194M)
- `gliner25-multi` → `fastino/gliner2.5-multi-v1` (287M, multilingual)

Public tasks:

- `extract_entities` / `extract_entities_long` — NER, PII spans, attributes
- `extract_records` — JSON / field schemas
- `classify_schema` — single/multi-label with optional constraints
- `extract_graph` — joint entity-relation decoding
- `redact_pii(..., backend="gliner25")` — same cached extractor

### Blog use cases

The example and Colab notebook cover the six Fastino GLiNER 2.5 use cases:
agent routing, agent guardrails, knowledge-graph memory, PII redaction,
contract review, and clinical span attributes.

### Install

```bash
pip install aibackends[gliner25]
```

## Performance

Measured on a 4-core x86_64 CPU with no GPU (full report in
`benchmarks/reports/2026-08-25_gliner25-small-cpu.md`):

| Scenario | Mean |
|---|---|
| First entity extraction (load + inference) | 4,859.1 ms |
| Warm entity extraction | 21.0 ms |
| Warm constrained classification | 20.4 ms |
| Warm joint IE | 65.4 ms |
| Warm long-document extraction | 203.2 ms |

Warm NER is about **232x** faster than the first call that includes model
loading.

Accuracy on the labeled use-case set (`evals/reports/2026-08-25_gliner25-small-cpu.md`):
**8/8 cases passed**, mean recall 1.00, mean F1 0.88 (precision is pulled down
by extra predicted labels on multi-label guardrail and clinical cases).
